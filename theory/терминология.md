# 📖 ПОЛНЫЙ ГЛОССАРИЙ (по твоим слайдам)

## 1. КЛЮЧИ

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Суперключ** (Super-Key) | Множество атрибутов, по которому нельзя найти два разных кортежа с одинаковыми значениями | `{Email, Название_игры}` |
| **Потенциальный ключ** (Candidate Key, CK) | Несократимый суперключ (убираем любой атрибут — перестаёт быть суперключом) | `{Email, Название_игры, Жанр, Разработчик, Название_достижения}` |
| **Ключевой атрибут** | Атрибут, который входит **хотя бы в один** потенциальный ключ | `Email`, `Название_игры`, `Жанр`, `Разработчик`, `Название_достижения` |
| **Неключевой атрибут** | Атрибут, который **не входит ни в один** потенциальный ключ | `Никнейм`, `Страна`, `Год_выпуска`, `Дата_получения` |
| **Первичный ключ** (Primary Key, PK) | Потенциальный ключ, выбранный в качестве основного (обычно один) | `Email` (если выбран так) |
| **Внешний ключ** (Foreign Key, FK) | Атрибут(ы), который является первичным ключом в **другой** таблице | В таблице `Gains` атрибут `Email` ссылается на `Players(Email)` |

---

## 2. ФУНКЦИОНАЛЬНЫЕ ЗАВИСИМОСТИ (ФЗ)

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Функциональная зависимость (ФЗ)** | Если значения `X` совпадают, то значения `Y` **обязаны** совпадать | `Email → Страна` |
| **Детерминант** | Левая часть ФЗ — то, **от чего** зависит | `Email` (в `Email → Страна`) |
| **Зависимый атрибут** | Правая часть ФЗ — то, **что зависит** | `Страна` (в `Email → Страна`) |
| **Тривиальная ФЗ** | Зависимый атрибут **входит** в детерминант | `{Email, Страна} → Email` |
| **Нетривиальная ФЗ** | Зависимый атрибут **не входит** в детерминант | `Email → Страна` |
| **Приводимая слева ФЗ** | Из детерминанта можно **убрать атрибут**, зависимость сохранится | `{Email, Название_игры} → Страна` приводима к `Email → Страна` |
| **Неприводимая слева ФЗ** | Нельзя убрать ни один атрибут из детерминанта | `{Email, Название_игры} → Имя_в_игре` (оба нужны) |

## 3. ОПЕРАЦИИ НАД ОТНОШЕНИЯМИ

| Термин | Определение | Пример |
|--------|-------------|--------|
| **Проекция** | Убираем часть атрибутов, одинаковые строки "схлопываются" | Из `R(A,B,C)` делаем `R1(A,B)` |
| **Декомпозиция** | Разбиваем отношение на **несколько проекций** | `R(A,B,C)` → `R1(A,B)` + `R2(A,C)` |
| **Декомпозиция без потерь** | При соединении проекций **получается исходное отношение** | По правилу Хеза |
| **Естественное соединение** | Соединяем таблицы по одинаковым атрибутам | `R1 ⋈ R2` |

---

## 4. НОРМАЛЬНЫЕ ФОРМЫ (только для 2НФ пока)

| Термин | Определение |
|--------|-------------|
| **1НФ** | Все атрибуты атомарны (нет списков, нет повторяющихся групп) |
| **2НФ** | = 1НФ + **нет неключевых атрибутов, зависящих от части составного ключа** |

---

## 5. ПРАВИЛА И ТЕОРЕМЫ

| Термин | Определение |
|--------|-------------|
| **Правило Хеза (Heath's theorem)** | Если есть ФЗ `X → Y`, то декомпозиция на `R1(X, Z)` и `R2(X, Y)` будет **без потерь**. Где `Z` — все остальные атрибуты |

---

## 6. ВИДЫ КЛЮЧЕЙ (дополнительно со слайдов)

| Термин | Определение |
|--------|-------------|
| **Естественный ключ** | Ключ, значения которого существуют в реальной предметной области (например, `Email`, `Номер телефона`) |
| **Суррогатный ключ** | Искусственно добавленный атрибут (например, `id_игрока`), используется вместо естественного |

---

## 📌 Как это всё запомнить (мнемотехника)

```
Суперключ — всё, что уникально
Потенциальный ключ — минимальный уникальный
Ключевой атрибут — часть любого ключа
Неключевой — не часть

Детерминант — тот, от кого зависят
Зависимый — тот, кто зависит

Тривиальная — часть сама от себя зависит
Приводимая слева — можно убрать лишнее

2НФ — никакой зависимости от половины ключа
```

## 🎯 Быстрая проверка себя

Ответь на вопросы (ответы в конце):

1. Может ли суперключ состоять из **всех** атрибутов отношения?
2. Если атрибут входит в потенциальный ключ, он **ключевой** или **неключевой**?
3. ФЗ `{Email, Страна} → Email` — тривиальная или нет?
4. Что такое детерминант в ФЗ `Название_игры → Год_выпуска`?
5. Какое правило гарантирует декомпозицию без потерь?

<details>
<summary>Ответы</summary>

1. Да, суперключом может быть **любое** множество атрибутов, которое уникально — даже все атрибуты.
2. **Ключевой** (по определению).
3. **Тривиальная** (зависимый атрибут `Email` входит в детерминант `{Email, Страна}`).
4. Детерминант = `Название_игры`.
5. **Правило Хеза**.
